# Style DNA, song map and stem light

Extends existing SAMADHI LOVE Studio from published version 86 (`d7983d266a02e63c7af06d9373b3bd891bf8a08e`). The latest source, including audited video repairs, photo stories, sacred templates and section editing, is retained. No account, library, provider setting, schema or access policy is replaced.

## Implemented

Create → Music Creation → My Style DNA & song map adds named private sound recipes using the existing per-account saved-template storage. They retain genres, instruments, vocal direction, BPM and section targets, without copying lyrics or overwriting the next song's title/story. Normal saved prompts remain separate in the same existing workflow. Loading a DNA recipe activates its map. Saving uses existing revision/conflict and ownership controls.

The optional song map offers Intro, Verse, Pre-Chorus, Chorus, Drop, Bridge and Outro. Drag to reorder on desktop or use accessible up/down buttons on phones. Add/remove sections; choose 40–240 BPM, 3–120 seconds per section and up to 16 sections, with an overall maximum of six minutes. Enabled maps supply the real generation request's tempo, arrangement directions and requested total duration. Disabling the map restores normal automatic prompt-based length. Musical ads keep their existing independent short lengths. Provider timings, instrumentation and vocal identity are targets rather than guarantees. Existing approved lyrics remain unchanged. Map directions are bracketed production instructions and do not become sung words.

Lyric Videos & Shorts → Choose look → Stem-reactive light accepts an authorized, already separated full-length audio stem. A saved vocal stem can also be reused. Real sample RMS/positive-transient envelopes are calculated through the existing AV analysis code and cached as compact source-linked features inside the private video project. No new paid separation request occurs. Duration must match the song within half a second; users confirm the stem starts with the song and can compensate a measured offset up to two seconds.

Choose transient pulses or smooth loudness glow and adjust strength. A restrained background light pulse runs through the same frame renderer in preview and export, beneath captions. Reaction features are ignored when their immutable recording ID does not match. Removing the effect leaves lyrics, caption timing, source audio and templates intact. File analysis can be canceled. Files are limited to 96 MB and the existing ten-minute decode limit; native browser decoding support varies.

The beginner video control currently uses one selected stem for light; the existing Audio + Visual Studio retains multi-stem/MIDI mappings. It does not claim live AI stem isolation, kick/snare classification, pitch-driven syllable timing or multiple new beginner visual mappings. Stem separation remains in the existing authorized Stems & MIDI workflow. Analysis features are saved, not a new uploaded copy of the local source stem.

## Validation and limits

Added tests verify private DNA serialization, map bounds, loading without replacing writing, actual generation payload tempo/duration/arrangement, analysis of real synthetic audio samples, source-time offsets, silent/out-of-range values, source-ID guards and project serialization/validation. Full regression and build results are recorded in STUDIO_CONSOLIDATION_QA.json. No real user data or paid provider calls are used in these fixtures.

Native browser/mobile rendering, file decoding, microphone hardware and live provider musical quality remain unverified because the required browser runner is unavailable. No new dependencies are installed. Existing release package, rights/metadata, video export and stem/MIDI tools are reused.

Biometric adaptive playback, Hum-to-MIDI, multiplayer live jamming, automatic distributor submission and additional server GPU infrastructure are deferred. These need separate service, privacy, cost and performance work. No perfect recognition, zero latency, universal mastering target or fixed 60 fps promise is introduced.
